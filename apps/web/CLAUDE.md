# CLAUDE.md — apps/web

Vite + React 19 + TanStack Router (file-based) + TanStack Query + Tailwind v4 + shadcn/ui (Base UI underneath).

## Conventions

- **Page routes live under [src/routes/\_app/](src/routes/_app/)**, a pathless layout ([\_app.tsx](src/routes/_app.tsx)) that renders the site chrome ([app-chrome.tsx](src/components/app-chrome.tsx): Header, `<main>`, Footer) once, so the header survives navigation. Pages render only their content; a new page goes in `_app/`. The root not-found/error pages render outside the layout and wrap themselves in `AppChrome`.
- Route with detail page that should NOT inherit parent layout: trailing underscore (`browse_.$category.$slug.tsx`). Breaks layout nesting, keeps URL clean.
- Search params are coerced with [lib/util/search-params.ts](src/lib/util/search-params.ts) (`searchInt` / `searchPage` / `searchText` / `searchFlag` / `searchEnum` / `parseVariantIndex`). Builds-list routes spread `buildsListRoute(defaultSort).routeOptions` ([builds-list-route.ts](src/components/builds/builds-list-route.ts)) so each route's default sort is written once. That UI default is separate from the API's per-endpoint default (`LIST_DEFAULT_SORTS` in [@arsenyx/shared/api/build-list](../../packages/shared/src/api/build-list.ts), read by the api and by `listQueryString` in [builds-list-query.ts](src/lib/queries/builds-list-query.ts) to omit a redundant `?sort`).
- String `href`s (nav tables, data URLs) go through [src/components/link.tsx](src/components/link.tsx) — TanStack `Link` for internal paths, `<a>` for external URLs. Fixed in-app routes can use the router's `Link`/`navigate` with a typed `to`.
- Warframe types come from `@arsenyx/shared/warframe/*`; web-only catalog shapes (`DetailItem`, `ItemsIndex`, browse tab order) live in [src/lib/catalog.ts](src/lib/catalog.ts), the image allowlist in [src/lib/image-url.ts](src/lib/image-url.ts). Heavy data is static JSON under `public/data/`, generated by [scripts/build-items-index.ts](../../scripts/build-items-index.ts) (`bun run build:items`); fetch it via `staticDataQuery(path)` ([static-data-query.ts](src/lib/queries/static-data-query.ts)), whose key is the path.
- **Data access owners:** API calls and their error mapping → `apiCall` ([api-client.ts](src/lib/util/api-client.ts)); query keys → the per-resource factories (`buildKeys` in [build-query.ts](src/lib/queries/build-query.ts), `orgKeys`, …); stored builds → `loadBuildData` ([build-codec-adapter.ts](src/lib/codec/build-codec-adapter.ts)); browser storage → [util/storage.ts](src/lib/util/storage.ts).
- **Layering:** pure build rules live in [src/lib/build/](src/lib/build/), rendering shared by viewer and editor in [src/components/build-loadout/](src/components/build-loadout/). Which folder may import which is enforced by `bun run check:layering` (rules and reasons: [scripts/lib/layering.ts](../../scripts/lib/layering.ts)).
- **The data version (`__DATA_VERSION__`)** is stamped into app code (Vite `define`) and into `index.html`'s items-index preload, both in [vite.config.ts](vite.config.ts). The edge Worker doesn't have it; it's bundled by wrangler, not Vite.
- **Inline `<head>` scripts** (theme-before-mount in both HTML entries, the home items-index preload) are injected by the `arsenyx:head-scripts` plugin from [src/lib/html-head.ts](src/lib/html-head.ts), which also owns the theme storage key `ThemeProvider` uses. Don't hand-write them into `index.html` / `embed.html`.
- **Framing is denied site-wide and re-opened only for the embed.** [public/\_headers](public/_headers) sends `frame-ancestors 'self'` for `/*`; the partner allowlist lives in `EMBED_FRAME_ANCESTORS` in [worker/index.ts](worker/index.ts) and is applied to the `?embed=1` response alone. It can't live in `_headers` — those rules match on path only, and the embed shares `/builds/<slug>` with the full build page, so a path rule would also let partners frame `/create` and `/admin`. **Adding a partner domain means editing the Worker, not `_headers`.**
- **Two build entries** ([vite.config.ts](vite.config.ts) `rolldownOptions.input`): the full SPA (`index.html` → `src/main.tsx`) and a router-less read-only viewer (`embed.html` → [src/embed-main.tsx](src/embed-main.tsx)). For `/builds/:slug?embed=1` the Worker ([worker/index.ts](worker/index.ts)) — and in dev/preview the `embedRewrite()` middleware in vite.config.ts — serves `embed.html` instead of the SPA (the SPA route has no embed mode), so a guide page's many iframes don't each boot the whole app. The embed must stay off the router/app-shell graph: import viewer pieces via deep paths (not the `@/components/*` barrels, which fail to tree-shake) and the embed fetches the build with `?view=0` (no view-count, browser-cacheable — see [build-query.ts](src/lib/queries/build-query.ts) + api `builds.ts`).

For TanStack Router specifics (loaders, search params, layout nesting) consult the upstream [docs](https://tanstack.com/router/latest) when needed.

## SEO / head management

Two layers emit head tags, and they must stay in sync:

- **Client** — every route sets `head: () => seo({...})` ([src/lib/seo.ts](src/lib/seo.ts)), rendered by `<HeadContent />` in `__root.tsx`.
- **Edge** — [worker/index.ts](worker/index.ts) runs on every HTML navigation (`run_worker_first` in wrangler.toml excludes asset dirs) and injects the same titles/descriptions/canonicals into the raw HTML, plus the apex→www 301.

The two layers emit identical values per tag (the rule and its one exception are in [CODING_STANDARDS.md](../../CODING_STANDARDS.md#edge-and-client-head-tags-are-identical)); build values come from [@arsenyx/shared/seo/build-meta](../../packages/shared/src/seo/build-meta.ts).

`index.html` deliberately has NO static `<title>` / `<meta description>` — it would be a third, always-stale source. Keep it that way.

**Adding a route:** add a `head`. A static page gets an entry in `PAGE_META` ([@arsenyx/shared/seo/site](../../packages/shared/src/seo/site.ts)) and `head: () => pageSeo(path)`; the Worker, the sitemap and the parity test in [worker/index.test.ts](worker/index.test.ts) all read that table. A noindexed page under a dynamic path gets a `NOINDEX_PATTERNS` entry (pattern + meta) instead, its route head reads the same meta (see `ORG_SETTINGS_META`), and it gets a parity case.

`/sitemap.xml` is emitted at build time by the `sitemap()` plugin in [vite.config.ts](vite.config.ts) from `items-index.json` plus the indexable `PAGE_META` paths. `public/robots.txt` is hand-maintained and must not `Disallow` a noindexed page (`PAGE_META` noindex flags + `NOINDEX_PATTERNS`); the Worker tests pin that.
